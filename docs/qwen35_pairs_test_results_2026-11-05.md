### 3.1 当前目标跟踪

test 的八组三目标对照中 state 为 8/8，history/latest 为 0/8。
dev 同样为 state 8/8、其余 0/8；两批合计 state 为 16/16。
这些组由每分区两类隐式更新、两种语言和两种顺序构成，每组测试三种不同原目标。

test 的 24 条隐式更新中，history 有 22 条在 old_goal/resume_goal 字段填写初始目标，dev 也为 22/24。
例如初始目标为岛台、历史已改为餐桌，当前要求“先前往独立浴缸，再去原目标”，
history 仍恢复 island，正确应恢复 table；state 在同组能随当前目标变化。
此现象支持历史更新跟踪不足的诊断，尚不能排除通用提示和 JSON 消息组织方式的影响。

### 3.2 缺少上下文的猜测

latest 的 24 条隐式更新原文全部返回 `status=ok`，没有正确的 missing_context 拒绝。
其中 18 条通过输出契约、六条因非法旧目标引用而不通过；
`unsupported_guess_count=18` 只计通过契约的更新，不能把余下六条解释为合理拒绝。
三条猜中隐藏任务答案，解释了任务匹配 39 与有依据决策正确 36 的差值。
八个隐式对照组中五组始终填写同一个引用，另三组也未实现合理拒绝。

### 3.3 拒绝与操作类型错误

state 的 24 条歧义/未知区域消息全部未正确拒绝。
“颜色暂不明确”的区域要求仍被选成已有红色/蓝色区域，部分触发重复禁区保护；
“紫色区域禁止通行”则被映射到红色/蓝色区域，个别输出甚至改成替换导航目标。

state 的两条明确更新错误都属于新增蓝色禁区：
一条对“保持原定目的地，不要进入蓝色区域”输出 bed→bed，另一条对英文同义要求输出 table→bed。
前者被契约拒绝，后者可应用但语义错误。这说明执行器可以阻止部分非法操作，无法保证语言解释正确。

## 4. 阶段结论与下一步

当前完成的是固定公共语言上下文下的一次更新预测。旧策略状态由固定规则构建，
不是该模型连续生成的状态；保留未变化字段仍由共享执行器保证。
模型别名和参数相同，不能替代权重版本和 GPU 服务设置的完整冻结。

下一步先分别检查两个因素，保持当前预测、提示和配置为固定基线：

1. **历史组织消融**：明确初始指令已收到、此前介入已改变任务，按时间排列并将当前消息放到末尾；
   只重新组织相同公开信息，不添加正确当前目标或评价答案。检查原目标混淆是否减少。
2. **拒绝判断消融**：另一个独立变体明确候选闭集、缺失上下文和歧义的拒绝步骤；
   单独评价拒绝改善与明确更新是否退化，避免同时改动多个因素后无法解释来源。

先在 dev 比较，旧 test 保留为固定回归集。test 已被观察，后续若根据其错误调参，
