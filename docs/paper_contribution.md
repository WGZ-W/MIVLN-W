完整实现后，这个项目希望形成的核心贡献是：让机器人在“人类意图会变化、人类帮助不保证即时到达”的条件下，持续理解任务、维护上下文，并自主决定何时行动、何时求助、如何恢复任务。

最终成果应包括一套明确的任务定义、一种可验证的导航与交互方法，以及能够测量交互收益的基准。

下面按整个项目的研究逻辑展开。

一、在任务定义上，研究“动态意图与异步帮助共同存在”的导航问题。

这里有两种性质不同的变化：

- 机器人需要帮助：人的要求没有变，机器人不清楚怎样完成。例如，不知道用户指的是哪张桌子。
- 人的意图发生变化：机器人原来理解正确，但用户临时改变目的地、增加禁区或插入任务。

完整项目希望把这两种变化放进同一个持续执行过程。人可以主动修改要求，机器人也可以主动请求澄清，而且双方的消息可能交错到达。

同时，人不需要持续监督机器人。机器人提问后，可能立即得到回答，也可能等待很久，甚至没有回答。这使系统需要同时处理：

> 任务要求的变化、机器人自身的不确定性，以及人类帮助的可用性。

已有研究提供了相关基础：CVDN 研究对话历史支持导航，HANNA 研究请求和利用语言、视觉帮助，LILAC 研究执行中的语言纠正。因此，本项目需要进一步证明这些因素共同出现时会带来哪些新困难，以及所提出的方法怎样解决它们。CVDN (https://proceedings.mlr.press/v100/thomason20a.html)、HANNA (https://arxiv.org/abs/1909.01871)、LILAC (https://arxiv.org/abs/2301.02555)

这一层面的创新目标，可以表述为：

> 建立面向动态人类意图、双向交互和异步人类可用性的连续导航任务。

这里的“动态”主要指任务要求与交互状态的变化；家庭场景本身可以先保持静态。

二、在任务表示上，研究“有选择地更新要求，并保留仍有效的上下文”。

完整系统需要维护的内容，远不止当前目的地：

| 信息 | 需要回答的问题 |
|---|---|
| 当前目标 | 现在应该去哪里？ |
| 有效约束 | 哪些区域不能经过？ |
| 暂挂任务 | 临时任务结束后要恢复什么？ |
| 已完成内容 | 哪些要求已经满足，不必重复？ |
| 已失效要求 | 哪些旧目标已经被取消？ |
| 空间与视觉历史 | “刚才那条走廊”“另一张桌子”指什么？ |
| 交互状态 | 正在等哪个问题的回答？回答是否仍然适用？ |

潜在的方法贡献是：把新语言解释成对当前任务的局部修改，并让修改与空间证据、执行历史保持一致。

例如，“先去充电座，再继续原任务”应当保存原任务；“不用去了，改去沙发”则应使原任务失效。两句话都改变了当前行动方向，但后续义务完全不同。

更重要的是，任务更新与视觉记忆需要相互作用。用户说“别走刚才那条走廊”，模型必须把语言约束绑定到已经观察过的空间，而不能只在文本里保存一句“避开走廊”。

完整实现还需要解决一个目前基础图没有展开的问题：消息到达时间与消息适用范围可能不同。

例如：

1. 用户要求去厨房桌子旁。
2. 机器人询问：“是靠窗的那张吗？”
3. 用户临时要求：“不用去厨房了，改去沙发。”
4. 之前问题的回答随后才到达：“对，靠窗的那张。”

机器人应识别最后一句是在回答旧问题，不能让旧回答重新激活已经取消的厨房任务。为任务版本、问题和回复建立关联，就是值得进一步落实和检验的具体方法设计。

这一层面的创新目标是：

> 构建与视觉空间记忆相结合、能处理保留、失效、恢复及消息适用范围的动态任务表示。

仅使用一个状态字典还不足以构成方法贡献。需要证明：模型能够从语言和观测中正确维护这些状态，并减少任务遗忘、错误覆盖和恢复失败。

三、在决策上，研究“何时值得与人交互，以及没有回复时怎样继续”。

完整方法需要统一处理导航动作和交互动作。

例如，机器人不确定某个门口是不是目的地。它可以：

- 继续移动，获取更多视觉证据；
- 向人提问；
- 在当前位置等待；
- 暂缓不确定的动作，先执行仍然明确且允许的部分。

哪种选择最好，取决于多方面因素：

- 继续走错的概率和后果；
- 自主观察能否消除歧义；
- 一个问题能减少多少不确定性；
- 人可能多久回复；
- 当前还剩多少时间和交互预算；
- 采取的动作是否容易撤回或恢复。

因此，拟研究的主动交互策略应当考虑：

> 求助可能带来的任务收益，是否值得付出沟通、等待和执行风险的代价。

这比简单地设置“不确定性超过阈值就提问”更完整。即使两个状态同样不确定，它们也可能需要不同决策：一个状态允许低成本探索，另一个状态继续执行会造成很大的恢复成本。

异步回复还会让“提问之后怎么办”成为方法的一部分。系统需要追踪尚未回答的问题，并在等待过程中继续判断任务和观测是否发生变化。

这一层面的创新目标是：

> 形成兼顾任务进展、失败风险、沟通成本和回复延迟的主动交互策略。

要证明它有效，应比较相近人类帮助预算下的表现。例如，达到相同成功率时是否提问更少，或者在相同提问次数下是否完成更多任务；还要观察回复延迟增加、部分问题无人回答时，性能如何变化。

四、在基准构建上，研究“怎样控制变量，测出交互本身的作用”。

完整项目的基准应当能够系统改变以下条件：

| 维度 | 要研究的差异 |
|---|---|
| 意图更新类型 | 目标替换、约束新增、子目标插入恢复等 |
| 发起方向 | 人主动介入、机器人主动求助、双方主动 |
| 事件时机 | 较早、适时、较晚 |
| 回复条件 | 即时、延迟、缺失 |
| 语言条件 | 明确表达、依赖历史、需要视觉消歧 |
| 场景条件 | 已见环境、未见环境 |
| 帮助预算 | 消息数量、等待时间、人类参与成本 |

有价值的数据设计，需要保证事件确实影响后续决策。例如，新增的禁区应与路线有关；目标替换应带来有意义的后续变化；求助场景应存在可辨认的信息缺口。

配对实验也需要有明确含义。这里有一个特别重要的区别：

改变任务的介入，会同时改变成功条件。
无介入时到达岛台成功，目标替换后到达沙发成功，不能仅凭这两条轨迹的成功率差异就计算“交互带来的提升”。

因此，完整基准需要分别控制：

- 任务真值是否发生变化；
- 策略是否收到或正确处理更新；
- 是否获得额外帮助；
- 帮助到达的时机和信息量。

例如，Follow 与 Ignore 可以在同一个更新后的任务要求下比较；无介入分支则用于衡量原任务能力和任务变化带来的执行代价。

如果研究某个事件后的不同选择，还应匹配事件前的物理状态和策略记忆。不同策略自然产生不同历史时，需要另行定义公平比较协议。

这一层面的创新目标是：

> 构建能够分析“什么交互、何时交互、对谁有帮助、付出多少成本”的可复现导航基准。

目前的固定任务、原始证据和配对检查，为这个目标提供了基础；完整的数据规模、语言多样性与异步交互条件仍需要继续扩展。

五、在评价上，研究“怎样同时衡量任务适应能力、自主性和人类负担”。

完整项目不能只报告到达率。至少要回答四类问题：

| 评价对象 | 需要衡量什么 |
|---|---|
| 任务适应 | 是否执行了最新有效要求，保留了应保留的任务？ |
| 导航与恢复 | 是否完成目标、满足约束和顺序，恢复代价多大？ |
| 主动交互 | 是否在有用的时刻提问，问题是否带来实际帮助？ |
| 人类负担 | 使用了多少消息、等待和人工参与时间？ |

评价器应独立维护任务真值，避免把策略自己的解释当作答案。任务成功还需要依据真实执行证据确认。

完整评测还应把能力拆开：

- 任务更新评测：固定导航后端，检查语言模型是否正确理解更新。
- 端到端导航评测：检查视觉、记忆、语言、交互和动作执行的整体表现。

这样才能判断一个方法失败在哪里。它可能理解了“新增禁区”，却没能把区域落地到环境；也可能任务理解正确，却在导航中失败；还可能主动求助过晚，失去了低成本恢复的机会。

这一层面的创新目标是：

> 建立能够区分任务理解、空间落地、交互决策与导航执行的联合评价体系。

评价体系最终应该帮助回答：方法的收益究竟来自更好的理解、更合理的求助，还是使用了更多人类帮助。

从论文成果的角度，完整项目最适合凝练成三类贡献：

| 最终贡献 | 应交付的实质成果 |
|---|---|
| 任务与基准贡献 | 动态意图、双向发起、异步可用性的统一协议，以及有明确事件和成功真值的数据集 |
| 方法贡献 | 结合空间记忆与任务状态的增量更新方法，以及考虑交互价值和回复延迟的决策策略 |
| 实验与分析贡献 | 在统一任务和帮助预算下，解释状态保留、求助时机及异步回复对任务完成和恢复的影响 |

项目最有潜力的创新性，来自这些因素相互耦合时提出的问题，以及方法对这些问题给出的可验证解决方案。 单独接入语言模型、使用记忆、支持提问、实现状态机，都需要进一步落实成具体机制，并通过实验说明作用。

下一步应先把完整目标中的第一条方法主张做扎实：利用已有三类任务，固定导航后端，实现独立语言更新模块，比较最新指令、历史拼接和结构化状态，输出更新错误、要求保留和恢复成功等指标。之后再增加主动求助与延迟回复条件。相关语言和主动交互入口仍需实现。
