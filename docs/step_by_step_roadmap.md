# MI-VLN 从零实施清单

本文档把 MI-VLN 拆成可以逐项验收的小任务。执行时遵循一个原则：

> 先用少量手工样例确定任务语义，再配置仿真并跑通单个闭环；单例稳定后，才批量生成导航指令和数据。

因此，现在不应该先收集大量导航指令。任务定义、数据格式和评测逻辑尚未经过真实轨迹验证时，大规模收集的数据很可能需要返工。

## 总体路线

```text
任务定义
  → 5 个手工样例
  → 本地任务逻辑验证
  → Habitat 最小环境
  → 单个无介入导航
  → 单个目标替换闭环
  → 10～20 条试验数据
  → 三类介入
  → 100 条原型数据
  → 标注与 baseline
```

## 阶段 0：确认当前工程可运行

### 目标

先验证项目中与仿真无关的任务状态、事件触发和评价器，避免以后把普通代码问题误判为 Habitat 问题。

### 任务

- [ ] 安装 Python 3.10 或更高版本；
- [ ] 在项目根目录创建独立虚拟环境；
- [ ] 运行全部单元测试；
- [ ] 运行目标替换 demo；
- [ ] 检查 demo 是否生成 episode、事件、轨迹和指标文件。

### 推荐命令

```powershell
python -m venv .venv
```


### 验收标准

- 所有测试通过；
- `outputs/demo_001/metrics.json` 中 `dynamic_success` 为 `true`；
- 最终目标是 `bedroom`，取消的旧目标是 `kitchen`；
- 同一个事件不会触发两次。

### 本阶段产物


## 阶段 1：冻结最小任务定义

### 目标

把第一个实验限制为“执行中替换目标”，暂时不处理禁区、子任务、语音和真人在线介入。

### 需要明确的内容

- [ ] 初始指令描述一个可验证的目标；
- [ ] 每个 episode 最多发生一次介入；
- [ ] 介入发生在两个离散动作之间；
- [ ] 介入后不重置位置、朝向、视觉历史和轨迹；
- [ ] 旧目标永久失效，新目标立即生效；
- [ ] 智能体看到自然语言，评价器读取结构化更新；
- [ ] 到达最终有效目标并执行 `STOP` 才算成功。

### 第一版动作

```text
MOVE_FORWARD 0.25 m
TURN_LEFT 15°
TURN_RIGHT 15°
STOP
```

### 验收标准

- `docs/task_definition.md` 中不存在互相矛盾的规则；
- 给定任意一条样例，可以唯一判断最终目标和成功条件；
- 不依赖“模型自己认为目标是什么”进行评测。

### 本阶段产物

- `docs/task_definition.md`；
- 一页术语表：initial goal、active goal、cancelled goal、intervention、trigger、STOP。

## 阶段 2：手工设计 5 个任务样例

### 目标

在仿真之前用极少量样例检查数据结构。这里是“设计样例”，不是“收集数据集”。

### 样例组成

每条样例至少包含：

```json
{
  "initial_instruction": "Go to the kitchen.",
  "initial_goal": "kitchen",
  "intervention_utterance": "Instead, go to the bedroom.",
  "task_update": {
    "operation": "replace_goal",
    "old_goal": "kitchen",
    "new_goal": "bedroom"
  },
  "expected_final_goal": "bedroom"
}
```

### 建议的 5 种情况

- [ ] 房间目标替换：厨房 → 书房；
- [ ] 房间目标替换：卧室 → 客厅；
- [ ] 物体附近目标替换：冰箱 → 沙发；
- [ ] 较晚介入：接近旧目标时改去新目标；
- [ ] 无介入控制组：保持初始目标。

### 验收标准

- 每条自然语言都能映射到唯一结构化更新；
- 新旧目标不会使用同一个位置；
- 无介入样例和介入样例能够共用相同的初始任务；
- 不出现“附近”“那边”等缺少视觉上下文时无法判断的表达。

### 本阶段产物

```text
configs/task_cases_v0.json
```

在本阶段不要自动生成几百条语言，也不要请外部人员标注。

## 阶段 3：配置 Habitat 最小环境

### 目标

只验证仿真器能够加载、观察、移动和计算路径。不要在安装环境的同时开发介入功能。

- Ubuntu 或 Linux 服务器；
- 独立的 Conda/Mamba 环境；
- 固定 Habitat-Sim 和 Habitat-Lab 的兼容版本；
- 第一版启用 Bullet，但暂不安装 Habitat-HITL；
- 先使用官方测试场景，之后再下载 HSSD。

### 任务

- [ ] 记录操作系统、GPU、驱动和 CUDA 信息；
- [ ] 创建独立 Python 环境；
- [ ] 安装匹配版本的 Habitat-Sim；
- [ ] 安装匹配版本的 Habitat-Lab；
- [ ] 加载官方测试场景；
- [ ] 保存一张 RGB 图像；
- [ ] 保存一张深度图；
- [ ] 执行前进和转向；
- [ ] 验证碰撞检测；
- [ ] 计算两个可导航点之间的最短路径；
- [ ] 把版本号和 commit 写入环境记录。

### 验收标准

- 一个脚本可以从头加载场景并退出；
- RGB、Depth、位姿和碰撞信息均能读取；
- 相同起点和动作序列能够复现相同结果；

## 阶段 4：跑通一个无介入导航任务

### 目标

在加入语言介入前，证明普通导航链路是正确的。

### 任务

- [ ] 下载并加载一个 HSSD 场景；
- [ ] 手工选择一个可导航起点；
- [ ] 选择一个明确的房间或物体目标；
- [ ] 生成 Oracle 最短路径；
- [ ] 按短距离离散动作执行路径；
- [ ] 在目标成功半径内执行 `STOP`；
- [ ] 保存每一步的 RGB-D、位姿和动作；
- [ ] 计算 Success、路径长度和 SPL；
- [ ] 导出轨迹视频。

### 验收标准

- 机器人没有传送或重置；
- 能稳定到达目标并正确停止；
- Oracle 路径、执行路径和指标能互相核对；
- 重复运行结果一致。

## 阶段 5：接入第一个介入闭环

### 目标

完成项目最重要的单个端到端实验：厨房目标在途中被替换为书房。

### 执行过程

```text
1. 初始目标：厨房
2. 机器人沿厨房 Oracle 路径执行
3. 在原路径进度约 50% 时触发介入
4. 发送：“不用去厨房了，改去书房。”
5. TaskState 将厨房标记为 cancelled
6. 从当前位置重新规划到书房
7. 到达书房目标区域后 STOP
8. Evaluator 判定 Dynamic Task Success
```

### 任务

- [ ] 编写 Habitat 环境适配器；
- [ ] 每一步先检查事件，再选择动作；
- [ ] 将自然语言发送给 agent 接口；
- [ ] 将结构化更新单独发送给评价器；
- [ ] 从介入时刻的位置重新规划；
- [ ] 保留介入前全部轨迹；
- [ ] 保存 TaskState 的每次变化；
- [ ] 生成对应的无介入反事实分支。

### 验收标准

- 两个分支在介入前具有相同轨迹前缀；
- 介入分支最终到达书房；
- 无介入分支最终到达厨房；
- 介入过程没有创建新 episode 或重置机器人；
- `dynamic_success = true`；
- 停在已取消的厨房时必须判定失败。

## 阶段 6：生成 10～20 条调试数据

### 目标

发现任务生成、路径规划和评价规则中的问题，而不是追求数据规模。

### 任务

- [ ] 使用 1～2 个场景；
- [ ] 采样 10～20 个基础任务；
- [ ] 每个任务尽量生成无介入和目标替换两个分支；
- [ ] 自动检查初始目标和新目标均可达；
- [ ] 自动检查介入确实改变最终目的地；
- [ ] 人工观看全部轨迹视频；
- [ ] 记录失败原因并修改生成规则。

### 验收标准

- 所有保留样本均可复现；
- 无不可达目标；
- 无模糊或错误语言；
- 无介入前轨迹泄漏；
- 每个指标都可以从轨迹重新计算。

## 阶段 7：扩展到三类介入

只有目标替换稳定后，再按顺序加入：

1. `add_constraint`：增加禁止经过区域；
2. `insert_subgoal`：插入临时目标；
3. `resume_goal`：完成临时目标后恢复原目标。

每增加一种操作，都必须完成：

- [ ] 更新任务定义；
- [ ] 更新 JSON schema；
- [ ] 更新 `TaskState`；
- [ ] 增加单元测试；
- [ ] 增加失败样例测试；
- [ ] 在 Habitat 中跑通至少一个单例；
- [ ] 为对应指标增加自动验证。

## 阶段 8：构建 100 条原型集

### 什么时候才开始收集或生成导航指令？

满足以下条件后再开始：

- [ ] 三类介入都已跑通单例；
- [ ] episode schema 不再频繁变化；
- [ ] 自动可达性过滤已经完成；
- [ ] 所有主指标能够自动计算；
- [ ] 至少 20 条调试数据已经人工复核。

### 数据生成顺序

```text
采样场景和起点
  → 采样初始目标
  → 计算 Oracle 路径
  → 采样介入类型和新目标/约束
  → 验证介入后仍可达
  → 选择触发窗口
  → 生成结构化 task update
  → 生成或标注自然语言
  → 渲染轨迹
  → 自动检查
  → 人工复核
```

不要反过来先写大量自然语言，再尝试寻找能够匹配它们的场景和路径。

### 原型集规模

- 5 个 HSSD 场景；
- 100 个基础任务；
- 每个任务最多生成 4 个反事实分支；
- 目标约 300～400 个有效 episode。

严格按以下顺序执行；完成一项后再进入下一项：

- [ ] **任务 1：安装可用的 Python，并运行当前单元测试。**
