## 3. 模型具体做了什么

### 3.1 state 能跟随当前目标变化

8 组三目标对照中，state 全部正确，history/latest 均为 0/8。
这里 8 组是两类隐式更新 × 两种语言 × 两种候选顺序，每组包含 island/bed/table 三种当前目标，
不是八种独立任务意图。state 能在本批数据上相应改变 old_goal 或 resume_goal。
明确的目标替换、临时子目标、禁区和显式旧目标对照在 state 下各为 12/12。

### 3.2 history 经常把初始目标当成当前目标

24 条隐式更新中，22 条把初始目标填进 old_goal/resume_goal。
例如初始指令为“前往厨房岛台”，历史已“改去餐桌”，当前消息为“改去深色沙发”，
history 仍输出 island→sofa_dark，正确应为 table→sofa_dark。
另一个例子中，初始目标为床、历史已改为岛台，history 把子目标后的恢复目标写成 bed，而不是 island。
这些原始输出支持“未正确跟踪历史中的目标替换”的诊断；不能仅据此确定是模型能力、提示理解还是消息组织导致。

### 3.3 latest 在缺少依据时仍然猜测

24 条缺少上下文的消息全部输出可执行更新，没有一次正确 missing_context 拒绝。
12 条隐式目标替换均把 sofa_light 当作 old_goal；隐式恢复在每个三目标组内固定填写同一个恢复目标。
八组对照均出现常量引用猜测；其中四条恰好匹配隐藏任务答案。
这解释了 latest 的任务匹配为 38，而有依据的决策正确只有 34。

### 3.4 拒绝与候选顺序仍是问题

沙发泛称的 12 条消息在三模式下均未正确拒绝。
state 在顺序 0 时六条均选 sofa_light，反转顺序后六条均选 sofa_dark，恰好对应这组候选的首项。
这提供了该歧义组中的顺序偏向证据，但不能推广为所有任务都依赖候选首位。
未知书架在 state 下只有 4/12 正确拒绝，七条直接输出不在候选集合中的新目标引用。

| 顺序对照（每对两条） | latest | history | state |

| 预测一致 | 23/36 | 21/36 | 26/36 |

state 的明确更新 24 对均一致且正确；其顺序敏感主要出现在歧义和未知引用组。
