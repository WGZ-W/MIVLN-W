# MI-VLN Benchmark 优先交付路线

更新日期：2026-11-10。项目当前优先构建可复现的 Benchmark，方法与模型作为支撑实验。
本文确定工作顺序，不修改既有协议和历史评分，不代表新数据格式或统一命令已经实现。

## 1. 第一版交付目标

交付一套其他研究者能使用的任务定义、场景/任务数据、Agent 输入约定、独立评价器、Oracle 与负对照、复现工具和说明。
研究对象是家庭导航过程中人类改变要求后，Agent 对取消、保留与恢复义务的处理。

- 静态家庭场景、单机器人、文本语言，每个 episode 零或一次人类介入。
- 三类任务：目标替换、新增禁区、子目标插入与恢复，分别记录协议版本。
- 动作前一次投递，介入不重置位姿、轨迹和策略记忆。
- 评价器维护独立真值，根据实际 STOP、轨迹和实例证据评分。
- Oracle 可直接使用正确结构化更新与几何，验证可行性和评价规则；不要求先完成三类模型闭环。
- 被测方法不必内部维护 `TaskState`。任务更新轨道可要求符号预测，端到端轨道可直接输出规定动作。

历史 v0.1 仅目标替换；禁区、插入恢复及其 `COMPLETE_SUBGOAL` 动作是显式扩展。
当前 v1 是待整理发布的范围，不能把既有多个实验协议直接称为已经冻结的统一正式版本。

| 语言模型基线 | 两/五候选导航各 30 episode、离线改写/顺序 60 请求、代表导航 15 episode 已验收 | 已有基线证据；不是新的独立基础任务集合 |
| 工程验证 | 271 项测试通过，核心环境跳过 74 项原生依赖测试 | 保留现有回归及原始证据校验 |

子目标旧目录顶层 `summary.json` 保留历史失败，最新结论来自
`outputs/hssd_subgoal_acceptance_2026-11-03/acceptance.json` 及逐项重审记录。
统一审计必须同时记录原状态、重审版本和原生动作证明，不能仅将非零返回码改成成功。
同一基础任务的条件、时机、措辞和重复验证不能分别计作独立任务。

## 3. 按顺序推进的交付清单

| 优先级 | 交付项 | 验收标准 |
| --- | --- | --- |
| B0，下一完整步骤 | 三类任务统一清单与只读审计 | 关联现有任务、版本、来源、计划分母与审核证据；缺失/失败保留；不改旧产物、不重跑 GPU |
| B1 | 第一版协议与输入权限表 | 三类更新、动作/完成语义、触发和预算定义清楚；公开语言/观测与评价真值物理分离；文档及适配测试一致 |
| B2 | 数据质量与语言审核 | 目标/区域有可核验依据；记录采样拒绝、标注来源、复核者/范围；代表视频完成人工审核 |
| B3 | 多场景数据与分组划分 | 先新增一个场景验证采集，再扩展；同场景/同基础任务的相关分支不会泄漏到规定的留出划分 |
| B4 | 统一评价和运行/导出接口 | 按任务类型复算指标，公开/私有导出可检查；固定分母；Oracle 与 Ignore 正确验收，故意错误被拒绝 |
| B5 | 最小基线套件 | Oracle、Ignore 和代表性实际方法按轨道声明信息权限；现有 Qwen 结果可复用；新增模型适配按数据/评测需要安排 |
| B6 | 可复现发布候选包 | 配置、任务/数据卡、安装与校验、示例、引用/贡献及版本更正流程齐备；资产按允许方式获取 |

具体原型规模在跨场景质检后冻结。约 5 场景、100 基础任务是既有规划目标，尚未实现，不把小批次变体数量充作规模达标。

## 4. 下一步 B0 的具体设计

输入优先使用原始三类 Oracle 集合：

```text
outputs/hssd_dataset_facing_001/
outputs/hssd_avoid_batch_001/
outputs/hssd_subgoal_timing_001/
outputs/hssd_subgoal_acceptance_2026-11-03/
```

新增适配层读取既有格式，不改写它们。规划中的统一逻辑字段包括：

- `scene_id`、`base_task_id`：追踪场景及共同基础任务。
- `task_type`、`protocol_version`、`trigger_protocol`、`timing`：保留真实语义，不仅靠 early/middle/late 标签。
- `case_id`、`condition`、`reference_id`：区分任务变体、实际执行条件与共享参考。
- `source_config`、输入哈希、原始运行状态、`audit_status`、`audit_evidence`：追溯配置、失败、重审和证据。
- 轨道/输入权限、审核状态、数据划分：缺少的项显式标为待整理，不伪造审核或 split。

预计输出任务索引、逐项审计表、覆盖统计和问题清单。统计分别列出基础任务、场景、任务类型、配置和实际 episode 数。
数据完整性、任务可行性、Oracle 成功、Ignore 按预期失败、人工审核完成度分别报告。
B0 不是新榜单，也不会把模型输出 JSON 的约定强制为所有 Agent 的表示。

**该统一清单/审计入口尚待实现，目前没有对应可执行命令。** 下一次实现应先完成只读适配和 CPU 回归，
再对现有资产导出首版清单；发现协议或证据缺口先记录，不自动启动新仿真或筛掉失败任务。

## 5. B1/B2 需要明确的问题

1. **禁区的可观察性**：现有 Oracle 使用任务定义的矩形区域，视频没有绘制禁区。正式任务须声明视觉标记、语义空间描述或轨道允许的区域信息；不能声称当前 Agent 已从 RGB 识别这片区域。
2. **时机可比性**：目标替换按参考剩余距离减少量选步，禁区/子目标按累计行程。分别记录协议；跨策略需明确外生时刻或实际状态窗口，不能直接混合标签。
3. **终点定义**：到配置停止点 0.3 m 不等于离物体表面 0.3 m；距离、朝向、实例可见性及子目标完成条件分别冻结。
4. **公开信息边界**：评价器可读精确坐标、网格、结构化更新和诊断；普通 Agent 获得什么由轨道决定。Oracle 和任务更新后端的特权须显式声明。
5. **指标解释**：`goal_update_compliance` 当前只检查停止目标，不能代替禁区或顺序遵从；禁区/子目标最优效率尚未定义，不能套用无约束 SPL。
6. **分支比较**：Follow/Ignore 按同一更新后的真值比较；无介入 Control 的要求不同。不同策略可有不同前缀，当前严格前缀核对适用于同一确定性后端。
7. **语言和数据质量**：已有改写是编写的明确开发表达，正式数据应记录独立复核与歧义处理；保持原始标注和更正历史。

## 6. 暂缓的工作与发布边界

模型禁区/子目标回调、进一步 history/state 或拒绝消融、主动提问、异步回复及任务版本推理后置。
已有模型入口和结果保留，作为基线资产，不为优先级调整重写旧代码或破坏其哈希。
端到端视觉导航仍是正式 VLN 能力轨道所需工作，不能用 Oracle 成绩替代其评测。
线上榜单/隐藏测试服务在协议、数据和本地评分稳定后再建设。
