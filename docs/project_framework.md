# MI-VLN 项目整体框架与实施路线

更新时间：2026-10-23。本文依据当前代码、配置和本地实验产物整理，区分“已有实现”“已经运行验证”和“后续设计”，作为现阶段的项目导航文档。本文不修改既有任务规范；未来新增规则仍需更新规范、代码和测试。

## 1. 项目最终要解决什么问题

构建一个面向家庭服务机器人的可复现导航 Benchmark：机器人根据初始自然语言指令自主导航，执行途中人类可以异步修改任务；机器人需要结合当前视觉、历史记忆与新指令更新任务，从当前位置继续行动，并正确完成最终有效的要求。

研究重点不是“收到一个新坐标后重新规划”，而是：

1. 理解新语言究竟是取消旧目标、增加约束，还是暂时插入任务。
2. 更新应该改变的部分，同时保留仍然有效的目标、约束和历史。
3. 将更新后的任务落地到具体环境，在不中断 episode 的条件下改变后续行为。
4. 独立、可靠地评价目标、路线和执行顺序是否满足要求。

项目定位为 **Benchmark-first，Method-second**：先建立可信的任务、数据与评测，再比较语言处理和导航方法。结构化任务状态是待检验的方法假设，不预设其一定优于其他 baseline。

## 2. 统一研究范围：长期愿景、第一版与当前实现

### 2.1 长期愿景

早期讨论与论文草稿包含三种交互方向：人主动介入（HI）、机器人主动求助（RI）、双方主动交互（MI）。机器人提问、人类回复延迟和暂时不可用，属于后续扩展，当前没有实现。

因此，项目可以继续使用 MI-VLN 名称，但现阶段的实验应明确称为“MI-VLN 的人类发起介入子问题”，不能声称已经实现完整的双向混合主动系统。

### 2.2 第一版 Benchmark 主线

- 单机器人、静态家庭场景、第一人称 RGB-D、文本指令。
- 短距离离散导航动作，每条 episode 为 0 或 1 次介入。
- 三类核心更新：目标替换、增加避让区域、子任务插入与恢复。
- 介入发生在原子动作之间，自动触发，可复现。
- 任务更新轨道与端到端导航轨道分别评测，隔离不同能力。

第一版不做语音识别、抓取放置、多人权限、多机器人、动态人群、真人实时主排行榜、连续动作抢占和机器人主动提问。

### 2.3 当前 v0.1 实际范围

当前只支持 `replace_goal` 和按步触发。`TaskState` 中虽然存在约束、挂起目标等字段，但并不代表相应操作已经实现。当前 Oracle 读取真实坐标和结构化更新，尚未根据自然语言推断任务。

已有规划文档的旧勾选框和论文草稿中的设想不是实施状态；当前状态应以代码、测试和实际输出为准。核心代码兼容 Python 3.9+，不要沿用早期文档中必须升级到 Python 3.10 的表述。

### 3.1 已有调试实验说明了什么

测试场景中的 10 个基础任务各运行 1 条参考导航，以及早、中、晚三组控制/介入分支，共 70 个 episode，全部成功；已生成 40 段视频。单独的 Ignore Intervention 负例不计入这 70 条。

这些结果证明当前任务更新、连续执行、配对检查和几何评价流程可运行，不证明语言理解、家庭语义导航或跨场景泛化能力。两处运动过滤器碰撞标记仍需人工复核：`task_004` 晚期、`task_009` 早期；自动成功不等于所有视频已经人工验收。

Ignore 负例在第 29 步收到事件，评价器改为 B，策略保持 A；最终在 A 停止，距 B 约 5.923 m，被正确判失败，响应延迟为 `null`。`negative_check_passed: true` 表示负对照符合预期，不表示导航成功。

### 3.2 HSSD 当前状态

场景 `102344280` 的 290 个声明依赖文件检查通过，运行时加载 134 个物体，输出 24 个朝向的 RGB-D 和原始语义图；包含静态家具的导航网格面积约 171.36 m²，有 5 个连通岛。

数据版本为 `4369cb9876214c7fbebcf552eb532380e4d287e4`，运行环境记录为 Habitat-Sim 0.3.3、Python 3.9.23、NumPy 1.26.4。

语义数据不能直接当作可靠目标真值：23 个实例的模板没有类别 ID，25 个实例的模板词表标签与 metadata 类别不一致。原始文件有 15 条区域标注，但运行时 semantic objects/regions 均为空。物体列表由 rigid object manager 导出，区域标注从原始文件单独导出，不应混为一谈。

HSSD 目前通过的是“加载、传感器、导航网格和参考路径检查”，不是“机器人已走到语义目标”。截至本文整理时，尚未发现 `outputs/hssd_targets_001/` 的目标近景检查产物。

## 4. 总体系统架构

应当分开管理真实世界状态、评价器任务真值和策略自身理解的任务状态。

```text
离线数据构建（允许访问特权信息）
HSSD 资产 → 语义核验 → 可达停止区域 → 基础任务与介入 → Oracle 过滤与人工复核
                                              │
                         保存语言 + evaluator-only 结构化真值
                                              │
在线执行                                       ▼
事件调度器 ──自然语言消息──→ Agent：视觉/语言历史 → 预测任务状态 → 导航动作
     │                                                    │
     └──结构化更新──→ 评价器任务真值                        ▼
                                      Habitat 环境适配器执行动作
                                              │
                          观测反馈给 Agent；真实位姿/事件日志供评价器
                                              │
                                              ▼
                         STOP、最终目标、约束、顺序、效率与失败归因
```

关键边界：

- **环境状态**：真实位置、朝向、传感器和场景状态；介入时不重置。
- **评价器任务真值**：由人工核验的结构化事件更新，决定任务实际上要求什么。
- **策略任务状态**：由策略根据可见输入自行维护，可以理解错误；评价器不能用它替代真值。
- **Oracle 策略**：单独标记的特权调试/参考方法，允许读取坐标、导航网格和结构化更新，不能冒充语言 baseline。

当前 follow/ignore 模式已经分离评价器与策略状态，但 follow 仍直接应用真值更新，未来需要换成独立的语言理解结果。

## 5. 核心模块及其职责

### 5.1 场景与环境适配

负责完整 HSSD dataset config、scene instance、家具、传感器、动作、碰撞、导航网格与版本记录。提供稳定的 `reset`、观测、原子动作执行、位姿读取和结束接口；这些接口是后续设计，不是现有公共 API。

当前 `check_hssd.py` 已支持 dataset config，但 `run_navigation.py` 仍以单个 `scene` 文件路径加载，不能只把旧 GLB 路径换成 HSSD 房屋网格就开始正式实验。需要把 dataset config、scene ID、已核验的 navmesh，以及 agent 高度/半径一起接入导航入口。Habitat-Lab 可在后续需要统一任务/训练接口时引入，不应把原方案中的平台选择误写为当前依赖已经全部接通。

### 5.2 语义目标与空间约束

建立“语言描述 → 稳定物体/房间引用 → 合法停止区域”的对应关系。物体引用应包含 scene ID、模板与源实例索引；运行时 `object_id` 仅作本次运行映射，类别 ID 不能代替实例 ID。

停止区域必须在导航网格上，不能直接使用物体原点或 AABB 中心。点到 AABB 的距离只是几何筛选，不证明隔墙可见，也不等于真实表面距离；需补充目标近景核验、必要的视线/实例可见性检查，并保存人工结论。

房间任务和禁区任务还需要将原始区域多边形转换为可查询的空间区域，检查坐标、高度、边界及重叠情况。原始标注文件存在，不等于区域判定器已经实现。

### 5.3 动态任务状态与更新

保留现有 `TaskState`，按版本扩展操作，不为新增字段一次性重写项目。

| 操作 | 目标变化 | 必须保持的内容 | 评价重点 |
| --- | --- | --- | --- |
| `replace_goal`，已有 | A 取消，B 生效 | 位置、历史、仍有效约束 | 不得以完成 A 代替完成 B |
| `add_constraint`，待实现 | 仍前往 A | 原目标及已有约束 | 满足新约束并完成 A |
| `insert_subgoal` 与恢复，待实现 | 临时 B，之后恢复 A | A 进入挂起栈而不是取消 | 顺序 B→A，最终正确停止 |

插入子目标需要先定义中间完成信号。当前 `STOP` 直接终止 episode，不能不加修改地拿它完成 B 后继续 A；必须在规范中明确自动到达确认或专门的阶段完成机制，再实现状态机和测试。

### 5.4 事件调度

当前在第 `k` 步动作选择前投递事件，且每个事件只投递一次。现有三档时机由无介入参考轨迹到 A 的剩余导航距离减少量选出，再冻结为步号：`progress = 1 - d_t(A) / d_0(A)`，不是动作数比例。

这适合当前确定性 Oracle 配对调试，不能直接等同于跨策略公平的语义触发。后续应另行定义策略无关的外生更新时刻，或由各策略实际进入的空间/进度窗口触发；二者分别标记、固定协议，不能混合汇总。未到达触发窗口、提前 STOP 或超时的样本必须保留并报告。

### 5.5 Agent 与规划后端

语言接口应接收初始指令、新消息、允许的视觉/历史观测，输出预测任务状态或下一动作。主轨道不把精确目标坐标、结构化真值更新、完整语义地图或 Oracle 路径交给被测策略；相对位姿/里程计是否提供需在轨道配置中固定。

建议先解耦“任务更新器”和“导航后端”，便于判断失败来自语言、目标落地还是导航。结构化方法维护显式状态；其他 baseline 可以维护自己的文本或隐状态，不要求所有方法都使用同一种内部表示。

### 5.6 评测、日志与可视化

独立读取评价器真值、实际轨迹和动作，不根据策略声称的目标判成功。保留每次事件前后位姿、任务快照、更新后路径、STOP 原因、错误与运行日志，允许离线重算指标。

## 6. Episode 数据与运行契约

以下是后续需要统一的逻辑分层，不是已经可由现有脚本读取的新 schema：

- **身份与复现**：schema 版本、episode ID、base-task ID、branch ID、场景和资产版本、种子、动作/传感器/网格参数。
- **Agent 可见部分**：初始自然语言、已投递消息、轨道允许的观测与历史。
- **Evaluator-only 部分**：初始结构化任务、目标实例和停止区域、结构化事件更新、禁区及所需子任务顺序。
- **触发配置**：触发机制、窗口/时刻、early/middle/late 标签及实际投递记录。
- **运行产物**：观测、位姿、动作、事件、预测状态与真值状态、指标、终止原因、人工复核结论。

新 schema 必须提供旧配置兼容或迁移入口；不要把设计示例当成可直接执行的配置。

必须保持的执行规则：

1. 动作前处理到期事件，每个事件只生效一次。
2. 介入不重建模拟器、不传送、不清空轨迹和策略记忆。目标视点的离线传送检查不属于导航 episode。
3. 固定目标调试要求在目标点 0.3 m 导航距离内执行 STOP；语义目标需另行冻结停止区域/可见性定义，不能把该阈值直接解释成离物体表面 0.3 m。
4. 约束从规定的生效时刻开始检查，不追溯处罚介入前合法经过的区域。
5. 保留超时、未触发、规划失败和错误停止，不通过换样本让结果变好。
6. 输出目录不覆盖旧运行；场景、navmesh、参数与输入哈希一致后才允许配对比较。

## 7. 数据构建与质量控制

执行顺序为：

1. 核验场景资产和语义，建立带来源与人工标记的目标目录。
2. 采样起点、朝向、目标与停止区域，检查连通岛、路径长度、目标可见性。
3. 运行无介入参考任务，排除不稳定 Oracle 或不合理停止点，但保留筛选与失败统计。
4. 构造对目标、合法路线或执行顺序有实质影响的介入。
5. 检查实际触发位置到更新后目标的可达性，以及响应窗口是否足够。
6. 生成结构化真值，再基于视觉证据撰写/标注自然语言，不先批量写语言再强行匹配场景。
7. 渲染并复核关键帧、轨迹和停止位置；第二位标注者验证语言含义。
8. 冻结 manifest、配置、语言版本和数据划分，再运行 baseline。

每个基础任务尽量形成无介入、目标替换、禁区、插入恢复分支；分支有效性分别检查，不要求无法满足条件的任务硬凑所有类型。

同一确定性策略的事件前分支可以检查轨迹与 RGB-D 前缀一致。不同策略本来可能走不同路线，不应强制其前缀相同。反事实分析需要相同事件前状态时，单独定义共享快照/前缀回放协议，并标明是否包含策略记忆；不能把现有“从头重跑并核验前缀”称为已经实现了完整快照分叉。

数据规模分阶段推进：先 1 个 HSSD 语义单例，再 10～20 个 HSSD 调试任务；稳定后以约 5 个场景、100 个基础任务、300～400 个有效分支为原型目标。这些是计划规模，已有 70 条坐标实验不能计作该语义原型集。

正式评测采用 scene-disjoint 划分；同一基础任务的全部分支、时机和语言改写必须放在同一 split。val-seen 与 val-unseen 分开报告，具体场景数依可用资产与质检确定，不照搬旧计划中的目标数字。

## 8. 评测轨道、baseline 与实验矩阵

### 8.1 两条第一版能力轨道

- **Task-Update Track**：语言模块预测更新与目标引用，固定导航后端执行，用于隔离任务理解。若后端访问真值地图/坐标，必须声明并统一授予，不把信息泄漏给语言模块；目标落地使用什么候选信息也要固定。
- **End-to-End Track**：策略通过允许的 RGB-D、语言与历史完成导航，不提供上述特权信息，测试完整闭环。

两条能力轨道都属于当前以 HI 为主的交互设置，与长期 HI/RI/MI 三种“交互方向”不是同一个划分维度。

### 8.2 对照与 baseline

| 方法/条件 | 作用 | 当前状态 |
| --- | --- | --- |
| 无介入控制 | 衡量基础导航，检查是否牺牲原任务能力 | 已有 Oracle 版本 |
| Ignore Intervention | 事件照常投递，策略不更新；检验错误行为能否被评价器拒绝 | 已有 Oracle 单例 |
| Latest Instruction Only | 仅用最新语言，检验是否遗忘仍有效任务 | 待实现 |
| Concatenate History | 拼接初始指令和介入文本，作为简单语言基线 | 待实现 |
| Structured Task State | 独立从语言推断并更新显式状态 | 待实现；现有真值状态机不是该语言模型 |
| Oracle Dynamic Planner | 特权结构化更新与导航参考 | 已有目标替换版本；HSSD 迁移待完成 |

Latest-only 在简单目标替换上可能完全合理，只有加入“保留原目标”的禁区任务或“恢复原目标”的插入任务，才足以检验状态保留价值。Ignore 是必要负对照，但不能单独支撑模型贡献。

实验按“介入类型 × 早中晚 × 方法 × 场景划分”分组，同时报告无介入结果。方法比较使用同一任务集合和信息预算，区分状态更新错误、指代落地错误、导航失败与评测故障。后续消融再检查结构化状态、历史记忆和视觉目标落地各自的作用。

## 9. 指标定义与解释边界

- **Dynamic Task Success**：最终有效目标、全部生效约束、所需顺序、STOP 与步数限制同时满足；当前只实现目标替换的简化版本。
- **Intervention Compliance**：满足的有效更新要求占比。当前 `goal_update_compliance` 主要检查最终停止目标，不是通用语言理解得分。
- **无介入 SPL**：固定任务的成功率加权路径效率；现有介入 episode 不使用原目标的普通 SPL。
- **Post-Intervention SPL**：`S × L*_post / max(L*_post, L_post)`，从真实介入位置开始计算。当前采用到目标点的最短路径；语义停止区域版本需统一 `L*` 的终点定义。对于禁区和插入任务，Oracle 还必须遵守新约束或子任务顺序，不能继续套用单个无约束目标点路径。
- **响应延迟**：当前是 Oracle 首次为更新目标规划动作的延迟，不是语言模型响应速度。未来应冻结可独立观测的行为判据，并另报模型计算时间；不能只因内部目标标签改变就判定已响应。始终未响应保留 `null`，并报告未响应比例。
- **约束违反、任务保留、恢复成功**：待实现。禁区检查应覆盖运动线段，避免只看离散端点漏检；恢复必须验证先 B 后 A，而非只看最终停在 A。
- **诊断指标**：路径长度、动作数、导航误差、碰撞标记、未触发率、超时率和分阶段失败率。

SPL 不是精确终点到达的证明：停止容差可能使实走距离小于目标点最短路，SPL 仍为 1，应同时报告终点误差。所有成功率保留失败样本的分母；正式比较按场景/基础任务统计不确定性，同一任务的三个时机不能视为三个完全独立样本。

## 10. 后续实施路线与验收门槛

### P1：完成一个 HSSD 语义目标替换闭环——当前最高优先级

1. 完成床 A 与沙发 B 的目标近景检查，确认实例及停止点。当前几何候选对应运行时床 ID 21、沙发 ID 55，起点到两点约 7.04/2.31 m，两点间约 9.34 m；这些仅是本次运行的候选，不是冻结目标。
2. 把完整场景配置、scene ID、网格和尺寸参数接入导航入口，保留旧测试场景兼容性。
3. 先在 HSSD 实际执行到 A 并 STOP 的普通 Oracle 导航，验证运动，不以静态最短路查询代替。
4. 根据参考轨迹确定有效介入时机；在同一基础任务上运行无介入、正确处理、忽略介入三种条件。
5. 输出完整轨迹、事件、状态、指标和视频，复核事件附近及最终停止片段。

**通过条件**：控制到 A 成功；follow 从当前状态转到 B 成功；ignore 停在已取消的 A 并被判失败；事件准确投递，位姿和历史连续，实际任务配置一致，目标可见性与语言描述已人工确认。

### P2：HSSD 小规模语义调试集

完成 10～20 个固定基础任务，覆盖不同实例和布局；迁移三档时机及负对照，保留全部失败原因。先建立可审计的目标目录与数据清单，不直接扩大训练集。语言/策略接口在此阶段固定，先确保不传入 evaluator-only 字段。

### P3：实现其余两类介入

先做禁区：定义区域、验证合法绕行路线、实现受约束规划和连续轨迹评价。再做插入与恢复：定义中间完成信号、挂起栈、恢复动作和顺序评价。每类先通过单例与反例，再以至少 20 条自动仿真样例为阶段验收目标；缺少合法替代路径的候选在数据质检阶段拒绝。

### P4：语言 baseline 与任务更新轨道

实现可独立替换的语言更新模块，比较 latest-only、拼接历史与结构化状态；在相同导航后端上测试三类介入。Oracle 和 Ignore 保留为参考与负对照；不需要先训练大型端到端模型才能开始这一阶段。

### P5：原型 Benchmark、标注和跨场景评测

扩展到约 5 场景/100 基础任务，冻结 schema 与场景划分；建立视频/关键帧标注与双人复核流程。标注工具可在稳定协议后开发，Windows 作为查看与标注客户端，不必部署模拟器。

### P6：端到端方法、正式 Benchmark 与论文

接入至少可复现的视觉语言策略，补齐基线、消融、未见场景和时机分析。数据卡记录采样规则、失败率、标注一致性与使用限制，论文只报告真实结果。确认范围、数据质量和资源后再决定正式规模。

### P7：长期双向主动交互

在上述闭环稳定后，加入求助动作、人类可用性、延迟/缺失回复和通信成本，分别建立 RI/MI 协议。届时才评价“何时提问”与双向主动性的收益。

## 11. 代码组织与工程原则

现有入口继续承担清晰职责：

- `mivln/`：纯 Python 的任务状态、事件与评价语义，不依赖 Habitat/NumPy。
- `scripts/check_hssd.py`：资产及单场景检查；`run_navigation.py`：原子导航循环。
- `scripts/run_intervention.py`、`run_ignore_intervention.py`：正/负对照和验收。
- `scripts/intervention_timing.py`、`debug_dataset.py`：时机配置、调试集合与汇总。
- `configs/`：可复现输入；`tests/`：状态、事件、评价、几何及模拟循环回归测试。
- `docs/`：规范、命令和决策；`latex/`：论文草稿；`resource/`：参考材料。

随着重复逻辑增多，再逐步提取 `mivln/simulator/`、`generation/`、`agents/` 和 `schemas/` 等模块；这些是建议目录，并非已经存在。不要为追求完整目录树先做大规模重构。

Linux 服务器负责仿真与实验。延续当前协作方式：代码与 CPU 测试先检查，GPU 实验由使用者执行，随后核查产物。每个阶段记录配置、版本、命令和验收；新增语义必须同时有正例与反例测试。

数据与输出不提交 Git，不改写原始 HSSD 标签来掩盖冲突。发布前核对所用版本的许可证及引用要求，只按允许范围发布任务、标注、评测代码和获取指引，不默认可以重打包原始资产。
