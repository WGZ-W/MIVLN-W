# Benchmark 介入关联分层与重启对照设计

日期：2026-11-17。状态：纳入后续数据采集与实验设计，尚未实现分层采集、标注入口或重启对照运行器；本文不改变已有任务标签、评分或实验分母。

## 1. 研究问题

在导航过程中接收人类介入后，保留历史观测、记忆和执行进展，能否比清空历史重新规划更可靠、更高效？这种收益是否随新旧任务的关联程度及已有进展的可复用程度变化？

待验证假设：关联较强且已有进展可复用时，持续执行相对重启的收益更大；独立任务的收益可能缩小。独立任务仍可能从已有地图或观测中获益，因此不预设其表现必然等于重启。强相关也不保证路径更短，实际介入位置、目标距离和折返需求须单独记录。

## 2. 三档关联及任务语义

| 关联档位 | 标注依据 | 语言设计示意 |
| --- | --- | --- |
| 强相关 `strong` | 延续或细化原有要求，或新旧目标具有明确的局部空间、功能联系；标注具体依据 | “去餐桌旁。”→“先去旁边的椅子，再继续去餐桌。” |
| 弱相关 `weak` | 新目标发生变化，仍共享部分区域、通道或环境上下文，但没有直接义务延续 | “去餐桌旁。”→“改去客厅的沙发。” |
| 独立 `independent` | 新任务与原任务缺少直接语义、功能及局部空间联系；仍记录可能共享的通道和环境知识 | “去厨房岛台。”→“改去卧室的床。” |

示例须绑定真实场景与可核验实例后才能采用，不能仅凭物体名称或措辞自动分档。关联标注必须在方法运行前完成，不得根据哪种方法收益大来倒推标签。边界不清的案例先标记待复核，不强行归档。

关联是新增分析维度，现有任务语义仍为目标替换、子目标插入与恢复、取消并停止。第一批先在**目标替换内部**构造三档，避免将插入任务的保留义务误当作强相关收益；例如同一区域中相关实例的替换可作为强相关候选，再审核其依据。随后在子目标任务内部扩展并单独报告。取消任务继续评价停止响应，不强行划入三档。

语义关联、空间接近与路线复用分别记录。一个简短类别标签不能替代这些证据，也不能用参考路线重合率直接定义方法收益。

## 3. 数据设计与审核

新增清单拟记录以下私有标注；字段名和几何计算口径在实现前冻结：

- 身份：`scene_id`、`base_task_id`、`case_id`、任务类型、协议版本、语言及实例证据版本。
- 关联：`relatedness_level`、`relatedness_rationale`、语义/空间关系说明、审核人及审核状态。
- 介入：原目标、新目标、触发协议与步数、实际投递位姿、是否已见过新目标。
- 复用证据：介入位置至新目标的参考测地距离、初始参考路线与更新后参考路线的共享部分、已观测区域及折返需求。路线比较需明确路径采样与重合容差，未定义前不得伪造数值。
- 配对：`pair_id`、共享前缀证据、模型/种子/预算、记忆保留策略及重启初始化记录。

原始指令与介入表达由真实实例关系驱动设计，避免三档使用明显不同的固定句式。尽量匹配场景、触发进度、更新后距离、路线难度、语言长度和指代难度；无法匹配的差异在结果中披露并分层分析。先小规模审核可行性，再冻结各档规模；不通过删除运行失败案例来追求均衡。

同一基础任务的措辞、时机与方法分支仍共享身份，不能增加独立基础任务计数；同场景相关样本遵守场景留出划分。关联标签、精确位置、参考路线和未来语言属于评价侧信息，不额外提供给普通视觉 Agent。

## 4. 与重启方法的配对比较

主对照共享完全相同的介入前轨迹、实际位姿、当前 RGB、新任务要求和介入后预算：

| 方法 | 介入时处理 |
| --- | --- |
| 持续执行 `continue` | 保留允许访问的历史观测、策略记忆和已建立的环境表示，接收介入后继续决策 |
| 重启规划 `restart_memory` | 保持机器人位姿，清空本 episode 的历史观测、策略缓存、地图及规划状态，以同一模型从当前观测重新决策 |

须声明模型实际有哪些可重置状态，并验证重启分支没有通过文件、会话或外部地图读回旧记忆。两分支提供相同的完整有效任务要求：子目标对照必须明确“先 B，再 A”，不能让重启方法因缺失 A 的身份而执行不同任务。首次试验建议为两分支提供相同的规范化有效任务文本；原始上下文理解能力可另作实验。

首批使用固定前缀、在动作前投递一次介入，并为两分支保留相同的原总预算剩余额度。共享前缀可以由声明特权的 Oracle 采集，但其后续配对结果仅支持“固定前缀条件下”的结论。完整端到端表现需另行报告各策略自己的前缀。

将机器人送回初始位置的实验如有需要，单列为 `restart_origin`，说明额外位移与预算口径；不与清空记忆的主对照合并。保留地图但清空任务规划可作为后续消融，用于区分环境知识和任务进展的贡献。

## 5. 指标与结果解释

按任务类型、关联档位报告固定计划分母、完整任务成功率、失败类型，以及介入后的实际路径长度、动作数、规划耗时和模型调用量。耗时对照固定硬件、计时范围和服务条件。

对于两方法均成功的配对，分别报告路径、动作、耗时差值；成本收益定义为 `C_restart - C_continue`，正值表示持续执行成本较低。可补充 `(C_restart - C_continue) / C_restart`，但分母为零时记为不适用并报告数量。配对效率表必须同时列出双成功样本数、仅单方成功数及双失败数，不能将较早失败解释成高效率。

各档比较同时检查距离、时机等混杂因素；重复条件按基础任务聚合，扩展到多场景后按场景报告波动。成功率与效率分别解释。现有单场景 Oracle/Ignore 结果用于验证可行性和评分，不能作为真实方法在三档关联上优于重启的证据。

## 6. 实施顺序与验收

1. 先实现版本化关联标注与配对清单入口，保留历史资产和分母；输出完整候选、依据、待复核项及缺失字段。
2. 在目标替换中审核三档小样本，检查真实实例、语言唯一指代、介入点和更新后可达性；确定几何证据与分档规则。
3. 实现同位姿、同前缀、同预算的重启运行器及独立审计；检查记忆重置和输入权限，再由用户运行脚本。
4. 完成配对实验并按档报告成功与效率；随后扩充场景、表达及子目标覆盖，不预先承诺收益排序。

本设计尚无可执行的专用采集或配对命令。当前可继续完成已有八条视频人工质检；新入口实现后再提供用户执行命令、预期产物和验收条件。
