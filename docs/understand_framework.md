先看总体图的三个部分。

| 部分 | 要回答的问题 | 图中内容的含义 |
|---|---|---|
| 任务与基准贡献 | 机器人要面对什么问题？ | 定义任务变化、交互方式、回复条件，构建可重复评测的数据 |
| 方法贡献 | 机器人怎样解决这些问题？ | 结合记忆更新任务，再决定导航、询问或等待 |
| 实验与分析贡献 | 怎样证明方法有效？ | 控制任务与帮助预算，通过比较、消融和失败分析检验方法 |

左侧的 “动态意图”，表示人的要求在执行途中可以变化；“双向发起”，表示人可以主动介入，机器人也可以主动提问；“异步回复”，表示提问和回答之间可能存在延迟，甚至没有回答。

“任务与事件协议”规定变化如何生效。例如，取消旧目标、新增禁区、暂挂原任务，分别意味着什么。协议还需要规定事件时机、任务完成条件，以及失败怎样统计。

“可复现任务数据”表示每个任务不仅有一句语言，还要有对应场景、起点、事件和正确要求。场景划分用于区分熟悉环境和未见环境，独立真值用于保存评价器判断成功所需的正确答案。

右侧的 “统一任务与人类帮助预算”，强调方法比较要尽量公平。一个方法如果获得更多提示或更长等待时间，其成功率就需要连同这些成本一起解释。

“配对实验”比较同一任务在不同处理条件下的表现；“模块消融”检查某个机制是否有用，例如移除历史记忆后，任务恢复是否更容易失败。

“联合评价与失败分析”则同时检查任务完成、恢复效率和交互成本，并区分错误来自语言理解、目标落地、交互决策还是导航执行。

总体图下方的 “独立任务真值，仅用于评价” 是一条重要的信息边界：正确答案送给评价器，策略依靠自己的输入形成任务理解。这样才能测出策略是否理解正确。

再看方法细化图中的七个模块。

1. “人类消息”：系统接收要求和回复的入口。

它包含三种来源：

- 初始指令，例如“前往厨房岛台”。
- 执行中的新介入，例如“先去沙发，再继续原任务”。
- 对机器人问题的回复，例如“我指的是靠窗的那张”。

注释 “即时或延迟的人类回复” 表示消息不保证立即到达。系统还需要判断一条回复在回答什么问题、是否仍适用于当前任务。

例如，机器人询问某张桌子的位置后，用户已经取消了桌子任务。随后到达的旧回答，就不应重新激活已取消的目标。

2. “语言理解与增量更新”：解释新消息应该改变哪些要求。

这个模块读取三类信息：新消息、已有任务状态，以及空间与历史证据。

注释 “解析意图与目标指代” 包含两个问题：

- 这句话要求做什么：取消、增加约束、插入任务，还是回答问题？
- 这句话指向哪里：“另一张桌子”“刚才的走廊”“原任务”分别指什么？

注释 “判断取消、保留或暂挂”，强调新消息与旧任务的关系。例如：
| 消息 | 应产生的更新 |
|---|---|
| “不用去岛台了，改去沙发” | 取消岛台，沙发生效 |
| “继续去岛台，但避开这片区域” | 保留岛台，增加约束 |
| “先去沙发，再继续原任务” | 暂挂岛台，完成沙发后恢复 |

“增量”的含义是：只修改受影响的部分，保留仍然有效的要求。

3. “动态任务状态”：保存机器人当前认为自己应该完成什么。

它需要记录当前目标、有效约束、暂挂任务、已完成内容和已经失效的要求。

例如，收到“先去沙发，再继续去岛台”后，可以形成：

当前目标：沙发
暂挂目标：岛台
恢复要求：沙发完成后返回岛台
原有约束：继续保留

注释 “关联任务版本与待答问题”，表示还要追踪任务变化与对话之间的关系：

问题：用户指的是哪张桌子？
问题所属任务：厨房桌子任务
当前任务是否仍有效：是或否
是否仍在等待回答：是或否

这样，延迟回答到达时，就能检查它是否仍然适用。

这里的任务状态是策略自己的理解，可能存在错误。评价器另有一份独立任务真值，用来判断策略是否做对。

4. “交互决策”：决定继续行动、提问还是等待。

这个模块综合有效任务、环境证据和执行进展进行选择。

注释中的三个量可以这样理解：

- 不确定性：当前对目标、路线或指令理解有多大把握？
- 风险：继续执行可能造成什么后果，恢复起来是否困难？
- 收益：提问或继续观察，预计能够改善多少后续决策？

“权衡提问与等待代价” 表示求助也有成本，包括打扰用户、等待时间和任务延迟。

例如，机器人看不清门牌时，可以先靠近观察；如果两条路线都合理，而且走错后返回代价很大，提问可能更值得。具体怎样估计这些量，是后续方法需要解决的问题。

5. “导航与等待”：把高层选择落实为持续执行。

交互决策决定“现在应该继续走还是等”，这个模块负责具体执行。

“按当前任务继续执行”意味着导航始终以最新有效要求为依据。例如，目标已经替换，就应调整后续路线；临时任务完成，就应转向恢复目标。

注释 “保留位姿与执行历史” 的含义是：介入时从当前位置接着执行，已经走过的轨迹和上下文继续保留。正常前进和转向仍会改变位姿。

图中的“等待”也是拟研究能力。它表示任务暂未结束、系统仍在等待消息，与结束整个任务的停止动作有不同语义；后续还需要明确等待如何计时和计入预算。

6. “环境执行”：执行动作并产生真实反馈。

在当前项目里，这一层由仿真环境承担。

“执行动作，返回视觉观测”表示动作执行之后，机器人才能获得新的视角和环境信息。计划中的前进与实际移动结果可能不同，因此后续判断必须参考执行反馈。

“记录位置与任务进展”用于回答：机器人实际到了哪里，临时目标是否已经完成，是否应该进入恢复阶段。

对未来的语言导航策略，能够读取哪些位姿信息、是否提供相对里程计，需要由评测配置统一规定。

7. “空间与历史记忆”：把过去的观察整理成可供后续使用的上下文。

它应积累地标、访问过的位置、路线和可通行证据，以及相关执行历史。

注释 “支持指代落地与任务恢复” 对应两种作用：

- 用户说“避开刚才那条走廊”时，帮助找到对应的空间区域。
- 临时任务完成后，帮助恢复原目标相关的信息和后续路线。

这个模块同时服务于任务理解和交互决策。机器人既要借助历史理解“用户说的是哪里”，也要借助历史判断“现在是否需要帮助”。

图中的箭头说明了这些模块如何配合。

| 箭头注释 | 传递方向 | 具体含义 |
|---|---|---|
| 新消息 | 人类消息 → 语言更新 | 接收初始要求、新介入或回复 |
| 更新结果 | 语言更新 → 任务状态 | 写入新解释出的目标、约束或恢复要求 |
| 已有状态 | 任务状态 → 语言更新 | 解释新消息时读取旧任务，支持选择性修改 |
| 有效任务 | 任务状态 → 交互决策 | 告诉决策模块当前仍需要完成什么 |
| 空间与历史证据 | 记忆 → 语言更新 | 支持“刚才”“另一张”“原任务”等表达的解释 |
| 空间信息与执行进展 | 记忆 → 交互决策 | 为风险、收益和求助判断提供证据 |
| 按需提问 | 交互决策 → 人类 | 选择提出澄清问题，随后等待或接收回复 |
| 行动或等待 | 交互决策 → 导航与等待 | 将高层选择落实为执行行为 |
| 动作 | 导航与等待 → 环境 | 实际执行移动、转向等操作 |
| 观测 | 环境 → 记忆 | 保存新观察，支持下一轮判断 |

顶部虚线用于突出与人类之间的交互路径。图中的颜色帮助区分模块，颜色和实线不表示完成状态；实现边界由底部说明给出。

底部三句话概括的是方法希望具备的能力。

- 增量更新任务：新要求只改变相关部分。
- 保留有效上下文：目标、约束、空间历史及问题关联能够延续。
- 权衡交互代价：根据收益、风险和等待成本选择是否求助。

用“先去沙发，再继续原任务”串起来看：语言模块读取已有岛台任务，解释出子目标插入；任务状态暂挂岛台、激活沙发；交互决策判断信息是否充分；导航模块从当前位置继续行动；环境反馈进入记忆；沙发完成后，系统恢复岛台要求并继续执行。最终由总体图中的独立评价部分检查真实的完成顺序和最终结果。

下一步适合把“语言理解与增量更新”进一步写成输入输出规范：给定消息、旧状态和允许的上下文，输出更新操作及更新后的状态，并准备三类任务样例检查要求是否被正确保留。相应语言实验入口仍需实现。
