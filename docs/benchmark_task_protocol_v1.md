# MI-VLN 第一版三类任务协议

版本：`v1.0-draft.1`；日期：2026-11-12。

范围更新（2026-11-13）：当前主采集采用 **目标替换、子目标插入与恢复、取消任务并停止**，见 [当前范围](benchmark_active_scope.md)。
新增第三类的状态、评分与入口见 [cancel_task_v1](cancel_task.md)；它取消目的地义务，并要求投递步立即 STOP，不要求到达物体。
本文保留原三类语义草案以兼容历史；禁区章节为后置扩展，旧评分和审计记录不改写。

## 1. 文档状态与适用范围

本文给出 Benchmark 第一版任务语义评审稿，统一说明目标替换、新增禁区、子目标插入与恢复。
“必须”表示本稿的规范要求，不代表已有统一公开接口或评分入口全部实现。
已有实现、历史协议差异及待适配项见第 11 节。当前主任务的公开输入和统一评分适配完成前，不宣称正式版本已经冻结；禁区问题后置。

首版范围为静态室内场景、单机器人、文本指令，每个介入 episode 恰好一种、一次人类发起的更新。
无介入参考及 Control 为零次更新。多轮介入、混合更新、嵌套子目标、主动求助、异步回复、动态物体和语音不在本稿范围。
本稿不修改历史 [v0.1 任务定义](task_definition.md) 和已有实验成绩。

## 2. 共同任务与真值

初始指令要求机器人前往指定物体实例 A。实例、导航停止点、语言描述及其绑定由数据制作和审核确定。
同类别的其他实例不能替代 A；用来朝向物体的中心与用于导航的停止点是不同几何量。
***评价器持有独立任务真值？***，依照已标注的更新、实测轨迹和完成证据判断结果，不能把模型预测当作正确答案。

| 信息或状态 | 用途与要求 |
| --- | --- |
| 场景及起始位姿 | 固定场景版本、种子、世界 XYZ 脚点坐标及 XYZW 单位四元数；距离单位为米 |
| 根目标 A | 初始要求对应的已审核实例及停止点 |
| 当前义务 | 评价器记录当前目标、取消/挂起/完成义务、有效约束；这是规范描述，不强制 Agent 使用相同数据结构 |
| 人类事件 | 唯一 `event_id`、投递步、自然语言消息及评价器私有更新标注 |
| 执行限制 | 固定动作、传感器、成功阈值和总动作预算；相同任务的比较条件必须一致 |
| 来源身份 | `scene_id`、`base_task_id`、`case_id`、`episode_id`、协议/触发版本、来源哈希与参考关联 |

同一基础任务的条件、时机、语言改写和重复运行共享分组身份，不能分别计作新的独立基础任务。

## 3. 动作、预算与 episode 生命周期

| 规范动作 | 当前 Habitat 日志名称 | 语义 |
| --- | --- | --- |
| `MOVE_FORWARD` | `move_forward` | 执行配置的名义前进量，实际位移由导航网格与碰撞过滤决定 |
| `TURN_LEFT` / `TURN_RIGHT` | `turn_left` / `turn_right` | 执行配置的水平转角 |
| `STOP` | `STOP` | 结束整个 episode；不移动，仍计为一个动作 |
| `COMPLETE_SUBGOAL` | `COMPLETE_SUBGOAL` | 仅子目标协议可用；提交一次中间完成声明，不移动、不结束 episode，计一个动作 |

初始化观测不计动作；动作从 0 编号。最多执行 `max_steps` 个动作，包括碰撞动作、转向、STOP 和中间完成动作。
介入投递、重规划和诊断不是额外导航动作；介入及恢复不能增加或清零原预算。
完成 B 恰好耗尽预算但尚未在 A STOP，仍然失败。最后一个允许动作若为满足全部条件的 STOP，则可以成功。
碰撞记录并计步；在首版中碰撞次数单独报告，不自动等于任务失败。

当前开发资产的参数如下，换版本或改传感器时必须重新声明，不得为某个失败样本临时放宽：

| 参数 | 当前值 |
| --- | --- |
| 名义前进 / 转角 | 0.25 m / 15° |
| 总动作预算 | 500 |
| 导航停止点成功半径 | 0.3 m，使用冻结网格上的 geodesic 距离 |
| 实例朝向阈值 | 水平角差绝对值 ≤ 7.5° |
| 独立实例可见阈值 | ≥ 64 像素，当前图像分辨率 256 × 256 |
| 禁区判定 Agent 半径 | 0.1 m，以任务配置和哈希为准 |

Oracle 的最多 24 次终点转向是现有控制器设置，不是要求所有参与方法使用相同控制算法。
名义前进量不保证每步欧氏位移恰好 0.25 m；异常投影必须有原生动作端点重现证明，不能任意放宽运动阈值。

## 4. 事件投递与时机

### 4.1 动作前投递

事件触发步 k 满足 `0 ≤ k < max_steps`。连续循环必须按顺序进行：

1. 保留执行完动作 k−1 后的位姿、观测和历史；k=0 时使用初始化状态。
2. 在动作 k 选择前投递事件一次，更新评价器真值，并向 Agent 提供该轨道允许的消息。
3. Agent 从现有状态选择动作 k，随后记录执行结果。重规划不得传送或重建机器人来清除历史。

当前轨迹第 0 行为初始化，动作 k 的结果在第 k+1 行；事件的 `delivered_step=k`。
子目标完成动作可在该动作内部恢复 A，因此其结果行可已显示 A；须结合完成前后证据核查，不能误判为未访问 B。
非法、重复投递或消息与标注不对应必须报告；Agent 不必接受正确更新，但评价真值不能随其拒绝或误解改变。

### 4.2 时机来源和比较

| 来源 | 触发口径 | 本稿处理 |
| --- | --- | --- |
| 历史目标替换 | 参考剩余 geodesic 距离减少 25% / 50% / 75% | 保留历史标识和 k |
| 历史禁区 | 参考累计实际行程 25% | 保留单一 early 配置 |
| 历史子目标 | 参考累计实际行程 25% / 50% / 75% | 保留原配置 |
| v1 新采集约定 | 统一使用参考累计实际行程，先换算并冻结 k | 尚需新采集适配，不回写历史 |

新约定中，无介入参考共有 M 个动作，最后一个是 STOP。动作 k 前的累计位移为 D(k)，总实际行程为 L。
对进度 p，选满足 `D(k) ≥ pL` 的首个合法 k，并要求 `k < M−1`，保证该参考动作尚非 STOP。
转向和零位移动作不增加行程；参考必须连续、成功且 L>0。多时机要求不同 k，否则记录准备失败，不能复用同一步假装三个时机。

同一配置向不同策略在同一冻结动作步 k 投递，不依据其自身路径重新选择百分比，因此不保证投递时机器人处于同一位置。
按实际状态窗口触发是另一种协议，需另行标识。不同历史进度口径不能仅因都叫 early 而合并比较。

有预定介入的评测槽位若在 k 前结束或异常退出，仍保留计划分母；本稿要求“完成介入任务”还必须实际收到该事件。
原目标静态到达可另行报告，不能替代介入任务成功。现有旧指标尚未统一实现此附加门槛，见第 11 节。

## 5. 目标替换

**示例：**“去岛台 A。”→“取消刚才的目的地，改去沙发 B。”

评价器私有更新示例；对象符号只是示意，不是新增 CLI 输入文件：

```json
{"operation": "replace_goal", "old_goal": "A", "new_goal": "B"}
```

- A 必须为更新前的当前目标，B 是不同的已绑定实例。规范标注明确写出 A/B，不依赖模型补全。
- 事件投递后 B 成为当前目标，A 被取消，原有约束与执行历史保留。
- 不再有完成 A 的义务；经过 A 不等于违规，在 A STOP 不能满足新的 B 义务。
- 完整成功要求：事件已投递，在预算内于 B STOP，满足第 8 节的点距离、朝向和实例证据。
- 在 A STOP、仅途经 B、未 STOP、目标不可达或证据不满足均不能成功。

规范数据应避免 A/B 的停止成功区域重叠。旧评价器在重叠时优先当前目标的兼容规则仍保留，不据此自动重审或剔除历史样本。

## 6. 新增禁区

**示例：**“继续去 A，但从现在起不要经过所指区域 R。”

```json
{
  "operation": "add_avoid_region",
  "region": {
    "region_id": "R", "type": "rectangle_xz",
    "bounds_xz": [[0.0, 0.0], [1.0, 1.0]],
    "floor_y": 0.0, "floor_tolerance_m": 0.5
  }
}
```

- A 不变；事件仅新增一个矩形地面约束，既有义务保留。示例坐标不是已验收场景配置。
- 世界 XYZ 单位为米，矩形采用 `[[min_x,min_z],[max_x,max_z]]`，Y 脚点带区分楼层。
- 评价矩形在 XZ 各外扩 Agent 半径，是保守方形足迹，不能称为精确圆形碰撞检测。
- 外扩后的闭边界及楼层带按现有 1e−6 m 几何容差检查，接触也算违规。
- 从动作 k 开始检查每个实际执行线段；端点都在外面但线段穿越仍违规，转向和 STOP 也检查所在位置。
- k 前经过 R 不追溯处罚。第一次违规即使之后绕出也不能消除；当前实现可以继续执行，到终点再报告联合失败。
- 违规计数按“违规动作数”，不是违规帧数；没有碰撞不代表没有禁区违规。
- 完整成功要求：事件已投递，之后零违规，并在原预算内于 A STOP，满足完整终点证据。

首版准备要求生效时机器人在外扩区域之外、A 保持安全且存在经验证的绕行路线，不包含“已经在禁区内如何逃离”。
禁区是逻辑规则，不是新增物理障碍，不修改原始网格。有限图 Oracle 没找到路线只表明该规划器失败，不能证明全局不可行。

**可观察性限制：**当前 Oracle 直接读取区域几何，历史 RGB 没有区域标记。
第一版公开视觉任务必须提供可确定 R 的语义或实际输入标记；若直接允许区域坐标，应单独声明受控几何输入轨道。
只在导出视频加框不满足 Agent 输入可观察性。此项尚未落地，历史禁区成绩只支持特权 Oracle 可行性与规则验证。

## 7. 子目标插入与恢复

**示例：**“去岛台 A。”→“先去沙发 B，然后继续去原来的岛台 A。”

```json
{"operation": "insert_subgoal", "subgoal": "B", "resume_goal": "A"}
```

- 更新前 A 是当前目标；B 与 A 不同。投递后挂起 A、激活 B，不能把 A 加入取消集合。
- B 的义务从介入后生效，介入前偶然经过 B 不能自动抵扣；必须在更新后提交有效完成动作。
- `COMPLETE_SUBGOAL` 必须对应当前挂起任务的 B；评价器独立确认距离、朝向和指定实例可见性后，才记录 B 完成并恢复 A。
- 完成动作不调用物理推进，不移动、不清空历史、不重置预算。恢复不是第二个人类事件。
- 策略声称已完成但证据失败时，评价器不得恢复 A。现有 Oracle 策略可能按自身声明恢复，两种状态必须分开保留。
- 首版只需一个 B 完成记录；重复完成、错误对象声明不能推进评价真值。统一外部动作接口对此仍需适配。
- B 处的 STOP 是终止整个 episode，不能解释成完成 B 后自动继续；只完成 B、漏做 B、完成 B 后未返回 A 都失败。
- 完整成功要求：事件已投递，有一次有效 B 完成、挂起义务已清空、恢复 A，并在剩余原预算内于 A STOP，满足完整终点证据及已有约束。

`point_goal_success` 针对评价器当时的当前目标；Ignore 到 A 时真值仍要求 B，所以该字段为 false。
`root_goal_success` 单独说明是否最终在原始 A STOP，不能单独证明 B→A 顺序完成。

## 8. 实测完成条件与结果分层

本节物体终点条件适用于目标到达型任务；新增取消任务使用独立的立即 STOP/位姿条件，不套用物体距离、朝向或可见性门槛。

点到达必须是实际 STOP 且从最终脚点到配置停止点的 geodesic 距离有限、非负、≤成功半径，并满足动作预算。
该距离不是物体中心距离、物体表面距离或画面距离；只报告策略意图或目标 ID 不足以成立。

完整终点及中间完成还要求面向对应实例中心，并有**指定实例**可见像素证据，不能合并同类别多个实例。
当前诊断使用临时独立标签，必须恢复标签、保持位姿且不推进动作；诊断图像和标签不得反馈给普通策略。
缺失、损坏或未执行的诊断是未知/证据无效，不能伪装成有效不可见，更不能判为成功。

| 结果层 | 含义 |
| --- | --- |
| 运行/证据有效性 | 输入绑定、日志、实际轨迹、投递和诊断能否核查；与任务成功分开 |
| 点/约束/顺序分量 | 分别报告停止点、禁区违规、B 完成与 A 恢复，不用一个目标字段替代 |
| 完整协议成功 | 实际投递要求、预算、正确最终 STOP、任务义务及朝向/实例证据全部成立；这是本文定义，尚无统一新字段 |
| 资产验收 | Oracle 按预期成功、Ignore 按预期失败及配对/来源检查；属于开发验收 |

已有 `success` / `dynamic_success` 保留历史意义，不自动改成完整协议成功；目标替换尤其不能仅用它证明实例可见。
合法执行但任务失败的参与方法仍是有效失败样本。提前 STOP、超时、策略错误及缺失运行均保留计划分母并记录原因。
数据或环境错误须独立标记，不能通过删行提高成功率；更正、重跑和发布排除须有事先规则及版本记录。

## 9. 条件设计、指标与证据

| 条件 | 事件及评分真值 | 当前确定性基线的预期行为 |
| --- | --- | --- |
| Reference / Control | 不投递介入，按原任务 A 评分 | 原始任务成功 |
| Follow | 投递并更新真值 | 替换后到 B；禁区绕行到 A；插入后完成 B 再到 A |
| Ignore | 投递并更新同一真值，策略忽略消息 | 沿原路线到 A，对更新任务失败 |

Ignore 并不是“没有收到介入”。负对照验收需要因被取消目标、实际禁区违规或缺失顺序而失败，不能用崩溃或超时冒充。
这只是负对照构造要求，普通参与方法不必模仿 Follow/Ignore 的内部状态。
Control 的任务真值不同，成功率不能与 Follow/Ignore 不加说明地合并成方法成绩。
配对条件固定场景、起点、种子和配置；逐行相同前缀仅用于现有同一确定性后端的工程核查，不强制不同方法走相同轨迹。

主报告按任务类型及场景列出计划数、实际投递数、有效执行数、成功数和固定分母成功率；另外报告分量结果、动作数、路径长度与碰撞。
路径长度累加实际相邻脚点的欧氏位移；均值必须给出样本数。缺失或未核验的成功声明不进入成功分子。
现有 `goal_update_compliance` 只检查停止目标，不能代表约束或顺序遵从。
现有响应延迟依赖策略状态/规划标签，只作已声明基线的诊断；尚非适用于任意 Agent 的统一理解能力指标。
禁区/子目标的 `post_intervention_spl` 保持 null；当前无约束 geodesic 或有限图路线不等于对应任务的最优可行代价。

评价证据至少保留配置及场景/网格/实例绑定、参考来源、事件实际投递、逐动作位姿与动作、STOP/中间完成、预算、违规及诊断哈希。
评价器从这些证据复核，不能信任参与方法自行填写的成功标志。缺失和失败槽位保留；人工审核另记审核者、日期、范围及更正。

## 10. 输入权限与发布前提

普通 Agent 只获得轨道明确允许的初始语言、已投递消息、实际观测及自身历史；RGB、深度、位姿、语义、地图和候选列表须逐项声明。
未来事件、正确结构化更新、私有精确目标和独立实例诊断不能随私有清单泄漏。
Oracle 可读取正确更新和精确几何，但成绩必须标注特权，不能作为端到端语言视觉能力成绩。
符号更新预测可以是独立轨道，不要求所有导航方法输出结构化状态。

[第一版输入权限表](benchmark_input_permissions_v1.md) 已单独列出 V/U/G/O/E 的组件边界和条件权限；
[U/G 消息契约](benchmark_public_inputs.md) 和 [V RGB 逐步输入、动作与标记字节契约](benchmark_visual_inputs.md) 已实现；真实导航、三维标记和完整隔离仍待验收。
本稿不授权将 B0 私有清单作为公开样本。
发布还需语言/视频独立审核、禁区可观察性、多场景与 scene-disjoint 划分、统一评价和可复现资产获取流程。
