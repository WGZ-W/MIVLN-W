## 主要信息流

**人类消息 → 语言理解与增量更新 → 动态任务状态 → 交互决策。**

语言更新同时读取已有任务状态和空间历史，确定需要取消、保留、新增或暂挂的要求。
空间记忆也向交互决策提供执行进展和环境证据，帮助判断当前是否需要求助。

交互决策可以选择导航、询问或等待。导航动作在环境中执行，观测反馈到空间与历史记忆；
询问发给人类，后续回复沿消息通道重新进入更新模块。

| 模块 | 核心输入 | 核心输出 |
| --- | --- | --- |
| 空间与历史记忆 | 允许的视觉观测、位姿信息与执行记录 | 地标、可通行信息和历史上下文 |
| 语言理解与增量更新 | 新消息、已有任务状态、空间历史 | 更新类型、目标引用及受影响的要求 |
| 动态任务状态 | 已解释的更新、执行进展与完成证据 | 当前有效目标、约束、恢复状态及交互状态 |
| 交互决策 | 有效任务、空间证据、不确定性与交互预算 | 行动、提问或等待的选择 |
| 导航与等待 | 当前任务与决策选择 | 后续导航动作或等待行为 |

## 三个需要检验的机制

1. **增量更新**：新要求只修改受影响部分，例如新增禁区时保留目的地，插入临时目标时保留恢复要求。
2. **上下文保留**：同时保留有效任务、空间历史及问题对应关系，避免延迟回复重新激活已取消目标。
3. **按需交互**：结合任务进展、风险和等待代价判断是否提问；没有即时回复时继续决策。

任务版本和待答问题关联属于拟研究设计。图中的状态是策略自行维护的状态，不能读取评价器正确答案。
允许的相对位姿或里程计由评测配置规定；不默认向语言策略开放完整场景或目标精确坐标。
导航阶段的完成判断也须通过策略允许的观测获得，评价器的独立诊断结果不回流策略。
