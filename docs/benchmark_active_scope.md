# 当前 Benchmark 范围：三类介入任务（不含禁区）

范围调整日期：2026-11-13。当前采用目标替换、子目标插入与恢复、取消任务并停止；禁区继续后置。
新增取消类型的实现与命令见 [cancel_task_v1](cancel_task.md)。本文件不代表新版完整数据集、筛选入口或统一评分已发布。

## 1. 当前主任务

| 类型 | 初始要求 | 介入后的义务 | 主评价条件 |
| --- | --- | --- | --- |
| 目标替换 `replace_goal` | 去 A | 取消 A，改去 B | 已收到介入，在 B 正确 STOP，并满足预算及实例证据 |
| 子目标插入 `insert_subgoal` | 去 A | 挂起 A，先完成 B，再恢复 A | B 有效完成，恢复 A，最后在 A 正确 STOP，满足原预算 |
| 取消并停止 `cancel_task` | 去 A | 取消所有未完成导航义务，不再要求到达目标 | 投递步的动作立即为 STOP，核查预算、位姿和取消后路程 |

三类分别检验更换目的地、保留/恢复旧义务和终止任务。维持静态室内、单机器人、文本语言、每个介入 episode 一次人类更新。
优先使用 `V_RGB_v1` 定义视觉输入；受控 U、Oracle 可继续验证语言接口、任务可行性和评价规则，输入权限须分别声明。
正确结构化更新是评价器标注，普通视觉方法自行选择内部表示；模型预测更新不是采集前提。

禁区因边界难以明确且视觉可观察性尚未落实，暂不进入后续主采集集、主结果表或近期导航接线目标。
历史区域逻辑、Oracle 实验、G 消息及红色标记合成检查保留，用于复现和未来扩展；不安排新的禁区任务或标记渲染作为当前前置步骤。

## 2. 数据和指标怎样调整

- 新采集范围明确包括 `replacement`、`subgoal`、`cancel_task`，记录新版本；取消准备及[语言标注/审核/语料导出入口](language_annotations.md)已实现，正式导航数据发布尚待完成。
- 后续主表分别报告三类完整成功率，总分建议为 `(SR_replacement + SR_subgoal + SR_cancel_task) / 3`；这一新统一评分尚需实现。
- Reference、Control、Ignore 单列，不混进参与方法的成功率分母。超时、缺失、错误预测和有效失败保持可追溯。
- 当前 B0 的历史三类是替换/禁区/子目标，仍为 10 基础任务、70 配置、220 episode；本次活跃三类使用取消替代禁区，不能混淆，也不改历史分母。
- 现有 `benchmark_audit` 和 `visual_inputs demo` 仍按原设计执行；取消使用独立版本入口，不自动修改旧数据类型或算作已完成的新正式评测。
- 旧协议及权限矩阵作为兼容性参考保留。禁止把排除禁区后的历史子集直接冒充新版正式 Benchmark。

## 3. 任务内优先丰富什么

初始语言和介入消息要对应可核验的实例，描述不能借用商品标签、私有 ID 或坐标。
在已有替换/插入语义下，先覆盖以下变化；取消语言也需清楚表达任务终止而非暂时暂停：

| 变化 | 示例与采集要求 |
| --- | --- |
| 同类实例纠正 | “不是深色沙发，改去浅色沙发”；两个实例均有视觉证据并可唯一指代 |
| 不同类别目标替换 | 岛台→沙发、桌子→椅子；绑定真实实例，不能只改名称 |
| 保留原目标的表达 | “先去 B，然后继续刚才的任务”；恢复指代必须能从已有输入唯一确定 |
| 早/中/晚介入 | 记录实际触发版本；新发布集统一参考累计行程后冻结，旧口径不回写 |
| 不同路线与恢复代价 | 记录到 B 的偏离及 B→A 的返回距离，验证能在原预算内完成 |

改写、时机和重复验证共享基础任务身份，不增加独立基础任务计数。同类纠正属于目标替换的难例，不单列成第三种任务语义。

## 4. 可选的后续介入类型

| 设计 | 例子 | 新增要求与建议 |
| --- | --- | --- |
| 多目标顺序调整 | “把顺序改成先 B、再 A。” | 需要初始多目标及已完成义务规则；暂不加入首批 |
| 暂停后继续 | “等一会儿，再继续去 A。” | 需明确等待时长、WAIT 动作/计时和预算；若人类再发恢复消息则超出一次介入范围，后置 |
| 返回起点 | “改为回到出发的位置。” | 可作目标替换场景变体；起点没有物体实例，必须另定终点证据，不能直接套物体可见性规则 |
| 目标澄清 | “我说的是靠窗的那张。” | 同类实例纠正可先按替换难例采集；真正允许初始目标不唯一的澄清任务需候选集合真值和歧义协议，另行设计 |

取消并停止已纳入当前第三类；本表其余设计仍为后续选项。暂停、多目标和歧义协议不作为当前采集前提。

## 5. 下一完整步骤

三类指令标注、审核和版本化语料导出已实现。用户确认全部文本及 RGB 后，首批 40 条模板语言以 WGZ 署名完成审核转录，已导出 30 个离线案例；原始待审版本保持不变。
已实现[已审语言三类 V 导航入口](benchmark_navigation.md)：

1. 绑定已审语言版本、基础任务身份和私有实例几何，保留原配置和运行结果，不把旧模型运行当成新指令验证。
2. 明确新版本参考累计行程触发及完整计划分母，保留历史触发口径；尚未冻结的字段不能静默补成已发布协议。
3. 接入逐步 RGB、实际动作及已投递语言；完整语料及私有标签不交给在线 Agent。
4. CPU 替身覆盖正确、忽略、延迟、语义错误动作和非法输出，独立检查替换、插入恢复、取消立即 STOP；合成几何/图像及特权策略单独声明，不能算 HSSD 执行。

审核与导出证据见 [语言工作流](language_annotations.md)，准备/CPU/只读重审命令见 [导航入口](benchmark_navigation.md)。
下一完整步骤是实现真实 Habitat backend，将实际 RGB、物理动作和独立实例诊断接入该循环；先验收一个基础任务的三类 Oracle/Ignore。真实运行命令尚未实现，不能把 CPU fixture 或离线语料当作真实导航配置。
正式大批次发布仍需协议/输入/评分冻结、跨场景划分和真实导航验收；试采集可以先开始并保留修订版本。
