# 当前 Benchmark 范围：两类介入任务

范围调整日期：2026-11-12。后续指令设计、试采集和正式评测优先采用目标替换、子目标插入与恢复；禁区后置。
本文件记录范围决策和下一步安排，不代表两类新版数据集、筛选入口或统一评分已发布。

## 1. 当前主任务

| 类型 | 初始要求 | 介入后的义务 | 主评价条件 |
| --- | --- | --- | --- |
| 目标替换 `replace_goal` | 去 A | 取消 A，改去 B | 已收到介入，在 B 正确 STOP，并满足预算及实例证据 |
| 子目标插入 `insert_subgoal` | 去 A | 挂起 A，先完成 B，再恢复 A | B 有效完成，恢复 A，最后在 A 正确 STOP，满足原预算 |

两类分别检验取消旧义务和保留/恢复旧义务。维持静态室内、单机器人、文本语言、每个介入 episode 一次人类更新。
优先使用 `V_RGB_v1` 定义视觉输入；受控 U、Oracle 可继续验证语言接口、任务可行性和评价规则，输入权限须分别声明。
正确结构化更新是评价器标注，普通视觉方法自行选择内部表示；模型预测更新不是采集前提。

禁区因边界难以明确且视觉可观察性尚未落实，暂不进入后续主采集集、主结果表或近期导航接线目标。
历史区域逻辑、Oracle 实验、G 消息及红色标记合成检查保留，用于复现和未来扩展；不安排新的禁区任务或标记渲染作为当前前置步骤。

## 2. 数据和指标怎样调整

- 新采集清单明确允许 `replacement`、`subgoal` 两个类型，记录新范围和版本；专用两类采集/发布入口尚待实现。
- 后续主表分别报告两类完整成功率，总分建议为 `(SR_replacement + SR_subgoal) / 2`；这一新统一评分尚需实现。
- Reference、Control、Ignore 单列，不混进参与方法的成功率分母。超时、缺失、错误预测和有效失败保持可追溯。
- 当前 B0 的三类清单仍为 10 基础任务、70 配置、220 episode；该历史审计及固定分母不改写。
- 现有 `benchmark_audit` 和三场景 `visual_inputs demo` 仍按原设计执行，不能声称已自动变成两类采集器或两类正式评测。
- 旧三类协议及权限矩阵作为语义/兼容性参考保留。禁止把排除禁区后的历史子集直接冒充已完成的新版正式 Benchmark。

## 3. 两类任务内优先丰富什么

初始语言和介入消息要对应可核验的实例，描述不能借用商品标签、私有 ID 或坐标。
在已有两类语义下，先覆盖以下变化，不新增任务操作：

| 变化 | 示例与采集要求 |
| --- | --- |
| 同类实例纠正 | “不是深色沙发，改去浅色沙发”；两个实例均有视觉证据并可唯一指代 |
| 不同类别目标替换 | 岛台→沙发、桌子→椅子；绑定真实实例，不能只改名称 |
| 保留原目标的表达 | “先去 B，然后继续刚才的任务”；恢复指代必须能从已有输入唯一确定 |
| 早/中/晚介入 | 记录实际触发版本；新发布集统一参考累计行程后冻结，旧口径不回写 |
| 不同路线与恢复代价 | 记录到 B 的偏离及 B→A 的返回距离，验证能在原预算内完成 |

改写、时机和重复验证共享基础任务身份，不增加独立基础任务计数。同类纠正属于目标替换的难例，不单列成第三种任务语义。

## 4. 可选的后续介入类型

| 设计 | 例子 | 新增要求与建议 |
| --- | --- | --- |
| 取消任务并停止 | “不用去了，现在停下。” | 可作为真正不同的后续第三类：取消导航义务，测实际投递后 STOP 延迟/位移；须新增终止语义和评分，不能沿用“必须到物体旁” |
| 多目标顺序调整 | “把顺序改成先 B、再 A。” | 需要初始多目标及已完成义务规则；暂不加入首批 |
| 暂停后继续 | “等一会儿，再继续去 A。” | 需明确等待时长、WAIT 动作/计时和预算；若人类再发恢复消息则超出一次介入范围，后置 |
| 返回起点 | “改为回到出发的位置。” | 可作目标替换场景变体；起点没有物体实例，必须另定终点证据，不能直接套物体可见性规则 |
| 目标澄清 | “我说的是靠窗的那张。” | 同类实例纠正可先按替换难例采集；真正允许初始目标不唯一的澄清任务需候选集合真值和歧义协议，另行设计 |

这些都是设计选项，尚无新增可执行任务入口。优先完成两类数据，再考虑“取消并停止”；暂停、多目标和歧义协议不作为当前采集前提。

## 5. 下一完整步骤

先实现两类指令标注表、审核和导出入口，V 真实 RGB/动作接线并行推进：

1. 基于现有 10 个基础任务，为每个任务整理一条初始指令、各一条替换和插入恢复消息，建立实例/来源关联。
2. 标注编写者、来源、审核状态、歧义及修改记录；缺少独立复核就标记待审核，不自动批准。
3. 在新文件中保存语言版本，保留原配置和运行结果；复用旧几何证据时声明用途，不把旧模型运行当成对新指令的验证。
4. 验收实例唯一、更新语义一致、只包含两类主任务、无私有答案泄漏且分组身份可追溯，再扩展场景和表达。

专门的指令采集/审核入口尚未实现，目前无需启动模型或 GPU。已有图片和已审核实例可用于试标注。
正式大批次发布仍需协议/输入/评分冻结、跨场景划分和真实导航验收；试采集可以先开始并保留修订版本。
