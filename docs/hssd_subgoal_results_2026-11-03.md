## 一个验收误判及修复

原始三时机汇总为 `passed: false`，29/30 配置通过，唯一拒绝项是 `task_004_middle`。
该项三条 GPU 分支均完整执行，Follow 也完成 B 后返回 A；错误来自旧检查器的动作位移上限。

第 64 步为 `move_forward`，名义前进量 0.25 m，实测位移 **0.281739725 m**，
超过旧检查器的固定上限 0.28 m。实测长度与轨迹记录一致，无碰撞标记。
在冻结网格、同一动作前位姿上，用无传感器原生 Agent 和 `PathFinder.try_step` 重新执行该动作：
重放终点为 `[-5.2234649658203125, 0.15372097492218018, -1.441969871520996]`，与记录的三维终点误差为 **0 m**。
这说明该步是原生网格过滤/投影的结果，不能用固定的欧氏距离上限直接判为传送。

修复采用 `native_projection_endpoint_v2` 检查：长度不一致、非移动动作发生位移仍直接失败；
超出旧上限的前进动作必须由相同原生动作和固定网格重放证明，终点误差须 ≤ 1e-5 m，不能简单放宽阈值。
没有改动导航策略、成功距离、可见像素阈值、任务、起点、目标或原始轨迹，也没有重跑 GPU。

该项原始子进程返回码 **1** 和旧失败汇总继续保留。
批量重审仅在原始三分支全部执行完成、新的完整原始证据检查通过、并具有明确原生投影证明时允许恢复验收，
报告为 `recovered_audit_cases: ["task_004_middle"]`；任意非零退出不会自动变成成功。
当前原目录的旧汇总仍反映历史检查器，最新结论以独立重审证据为准。
